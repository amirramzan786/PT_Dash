# Project Steel mobile packaging

Steel is packaged with Capacitor so the existing React/Supabase app remains the
single product surface for web, iPhone and Android. The native projects are
shells around the production Vite build; they do not replace the web app or
duplicate authentication/data logic.

## What is included

- `android/` and `ios/` native projects generated by Capacitor.
- A build-and-sync workflow that copies the current web build into each native
  shell.
- A stable placeholder application identifier: `com.projectsteel.app`.

## First local device run

From `webapp/`:

```sh
npm install
npm run mobile:sync
npm run mobile:android
# or
npm run mobile:ios
```

Android requires Android Studio and its SDK. iOS requires Xcode and an Apple
developer signing team. Neither store signing nor a store submission is part of
this scaffold.

## Before beta distribution

1. Confirm the final bundle identifier is available in both Apple Developer and
   Google Play. Change `appId` in `capacitor.config.ts` before the first store
   build if a different identifier is required.
2. Add the production and preview URLs used by Supabase Auth to its redirect
   allow-list. Native deep-link redirect handling is deliberately not enabled
   until the product's URL scheme / universal-link domain is chosen.
3. Test sign-in, sign-out, password reset, uploads, and all authenticated data
   flows on real iOS and Android devices.
4. Add privacy manifests, app-store privacy disclosures and production icons /
   launch assets before submission.
5. Implement Apple Health and Android Health Connect only through reviewed
   native plugins with explicit consent, revocation and deletion paths. This
   scaffold does not claim any device health-data integration.
